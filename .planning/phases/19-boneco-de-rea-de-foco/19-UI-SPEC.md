# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** On the Resumo card **Áreas de foco**, split each arm after the shoulder and split the limb below the knee, and make selecting a region leave the page scroll where it is. Front and back stay side by side. The 500ms hover chip stays the only write control.

**Sources:** `19-CONTEXT.md` D-01–D-08; `19-RESEARCH.md` Patterns 1–4 and the 42-key table; `06-UI-SPEC.md` (approved) for card chrome, chip, color, type, and copy that this phase keeps; live `PatientFocusAreasPanel.tsx` and `src/index.css`.

**Do not restyle** the forest sidebar, `Button`, `Input`, `PageHeader`, `Select`, `Modal`, `ConfirmDialog`, `ToastViewport`, or AppShell. Do **not** add shadcn, a body-map library, a sex selector, muscle-level regions, or finger/toe splits.

## Interaction Contract

Constant: `HOVER_OPEN_MS = 500`.

Fine pointer means `matchMedia('(hover: hover) and (pointer: fine)')`. Reduced motion means `matchMedia('(prefers-reduced-motion: reduce)')`.

| Action | Behavior |
|--------|----------|
| Fine pointer enters a region (`canWrite`) | Start a 500ms timer. Do not open immediately. Do not write. |
| Fine pointer stays 500ms | Open the chip for that `region_key`. Preview fill if unmarked. |
| Pointer moves from the path onto the chip | Chip stays open. No close timer. |
| Fine pointer leaves the region and the chip | Clear the timer, close the chip, drop the preview. A saved fill stays. |
| Click or tap the silhouette alone | Does **not** mark or unmark. On a coarse pointer, that tap opens the chip immediately. |
| Click or tap the chip | Toggle that region. Close the chip after success. |
| Coarse pointer, tap a region | Open the chip immediately (skip 500ms). A second tap must hit the chip to toggle. A tap outside both figures closes the chip. |
| `prefers-reduced-motion: reduce` | Delay is 0. Open on hover the same way as the keyboard. Do not animate the chip. |
| `!canWrite` | No chip, no tab stop, no preview. Saved highlights remain. |
| Double activation while `isPending` | Ignore the extra click. |

### Scroll

Selecting a region must not change `scrollTop` of `.panel-scroll`. Hover 500ms, opening the chip, clicking the chip, keyboard focus, and Escape are all “selecting” for this rule.

Remove `preservePanelScroll`. Reading `scrollTop` inside `onFocus` and writing it back records the jump. Do not put that helper back.

Do this, in order:

1. On `pointerdown` of a focus-card path, call `preventDefault()` so the click does not focus the path.
2. On `pointerdown` of the chip, call `preventDefault()` so the click does not focus the button. The `click` event still runs and calls the toggle.
3. When `canWrite`, each path is `tabIndex={-1}` (programmatic, out of Tab order). Each figure wrapper is one Tab stop (`tabIndex={0}`). When `!canWrite`, wrappers and paths have no `tabIndex`.
4. Arrow keys on a focused figure move among that figure’s regions in `<path>` order, wrapping, and call `path.focus({ preventScroll: true })`. That opens the chip immediately, with no 500ms wait. Hover that moves focus uses the same `focus({ preventScroll: true })`.
5. If the chip itself must be focused, call `chip.focus({ preventScroll: true })` after it is positioned. Never call `focus()` without `preventScroll: true`.
6. Escape closes the chip and returns focus with `path.focus({ preventScroll: true })`.
7. Remove the SVG attribute `overflow="hidden"` and the class `overflow-hidden` from the `<svg>`. Use `overflow-visible` so the SVG is not a scrollport. Keep `[overflow-anchor:none]` on the figure group. Do not portal the chip.

`BodyMapPicker` gets the same `pointerdown` `preventDefault` and `focus({ preventScroll: true })` rules. Its click still toggles the evaluation mark. It has no chip.

Proof, with the card already visible and not at the top of `.panel-scroll`: hover 500ms and click the chip on **Palma da mão** and on **Pé**. `document.querySelector('.panel-scroll').scrollTop` is the same before and after. Repeat a direct click on the evaluation map.

### Fallback if the page still scrolls

Use this only after the steps above still change `scrollTop`. Do not start here.

- Paint paths are visual only: no `tabIndex`, `pointerEvents="none"`.
- One HTML `<button type="button">` per region, placed with `getBBox()`, transparent, with the path `aria-label`.
- Each hit button calls `preventDefault()` on `pointerdown`.
- On the Resumo card, activating that button **opens the chip**. It does not toggle. The chip remains the only write control.
- On `BodyMapPicker`, activating that button keeps today’s direct toggle, because that surface has no chip.
- A new SVG that puts `tabIndex={0}` back on each path is not a fix. Do not ship it.

Focus ring stays the existing `:focus-visible` rule (`outline-2 outline-offset-2 outline-accent`) on the wrapper, the path, and the chip. Do not draw a second ring.
