# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** No cadastro a pessoa escolhe autônomo, empresa ou fisioterapeuta. Empresa aloca equipe por código + aceitar/recusar. Fisio pendente não entra na clínica. Autônomo não vê Equipe.

**Sources:** tokens from `src/index.css`; chrome from `AuthLayout`, `RegisterPage`, `ProtectedRoute`, `AppShell`, `PageHeader`, `Select`, `Input`, `Button`, `ConfirmDialog`, `Badge`, `DataTable`; product copy from `03-CONTEXT.md` (D-01–D-07) and `03-RESEARCH.md` (auth state machine).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside chips |
| sm | 8px | Label-to-control gap (`space-y-2` already on Input/Select) |
| md | 16px | Default padding inside list rows and code card inner padding |
| lg | 24px | Section gap between código / pendentes / equipe ativa |
| xl | 32px | Vertical padding on waiting/rejected cards (`p-8`) |
| 2xl | 48px | Unused this phase |
| 3xl | 64px | Unused this phase |

Exceptions:

- Register field stack stays `space-y-5` (20px) to match the existing `RegisterPage` — do not change the gap between Nome / E-mail / Senha.
- Icon-only “Copiar código” control: minimum hit area **44×44px** (pad the icon button; do not ship a 16px tap target).
- Existing `Button` padding (`px-6 py-3.5`) and `Input`/`Select` (`px-4 py-3.5`) stay as implemented.

## Typography

Exactly four sizes and two weights for **new** copy in this phase:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px (`text-sm`) | 400 | 1.5 |
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Heading | 20px (`text-xl`) | 600 | 1.2 |
| Display | 30px (`text-3xl`) | 600 | 1.2 |

Hints, inline errors, and `Badge` text stay at **12px** (`text-xs`) because `Input`/`Select`/`Badge` already render that size — do not invent a fifth size; do not change those components.

Existing chrome exceptions (do not restyle):

- `PageHeader` title remains `text-3xl` / `sm:text-4xl` / `lg:text-[2.125rem]` at weight 600.
- `Input`/`Select` labels remain `text-sm font-medium` (500) inside those components.
- `AuthLayout` marketing aside remains `font-display text-5xl`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f3f5f8` (`canvas`) | Clinic pages (`/equipe`), waiting/rejected full-bleed background |
| Secondary (30%) | `#ffffff` (`surface`) + `#0b1d36` (`forest`) | Cards, tables, auth form card; sidebar/nav stays forest |
| Accent (10%) | `#2f7dff` (`accent`) | Reserved list below — never body text or primary buttons |
| Destructive | `#dc4a4a` (`error`) | Recusar, inline/server errors, rejected-account icon well |

Accent reserved for:

1. Focus ring on `Input`/`Select` (`focus:border-accent` + `focus:ring-accent/25`) — already in those components
2. Empty-state icon well (`bg-accent-soft` / `text-accent`) on `/equipe`
3. Badge “Na equipe” (`Badge` tone `success` or `info` — accent-soft + forest/accent text)
4. Copy-success toast is **not** accent-colored; toast uses the existing `toast()` chrome

Accent is **not** for: primary `Button` (stays `bg-forest`), page titles, body copy, “Recusar”, sidebar active item (stays `bg-white/10`).

Auth screens keep the existing `auth-shell` dark canvas + white `auth-form-card`. Do not redesign login/cadastro chrome.

### Login (pending / rejected session)

If the user has a session but is not `isAuthenticated`:

- Pending → redirect to `/aguardando` (do not show the generic inactive card).
- Rejected (`is_active = false` + membership rejected) → Pedido recusado card.
- `GuestRoute` must **not** send pending/rejected sessions to `/painel`.

Login form server error when a rejected user tries the same e-mail after sign-out:

> Pedido recusado. Use outro e-mail para um novo cadastro.

## Screens

### 1. Cadastro — tipo + código condicional

- Extend existing `RegisterPage` inside `AuthLayout`. Do not add a second step/wizard.
- Field order: Nome → E-mail → **Tipo de conta** → **Código da empresa** (conditional) → Senha → Confirmar senha → mostrar senhas → **Criar conta**.
- `Select` required; first option value `""` labeled “Selecione o tipo”.
- Código: `Input` text, `autoComplete="off"`, `spellCheck={false}`, `autoCapitalize="characters"`. Normalize trim + uppercase + strip spaces before validate/submit.
- Código visível somente se `accountType === 'fisioterapeuta'`.
- Server/RPC errors use the existing `role="alert"` banner (`border-error/30 bg-error/10 px-4 py-3 text-sm text-error`).
- After fisioterapeuta signup with an immediate session, do not show “Você já pode entrar.” Route them to `/aguardando`.

### 2. Aguardando aprovação

- Full-viewport `bg-canvas`, centered card: `max-w-md rounded-3xl border border-line bg-surface p-8 text-center shadow-[0_18px_50px_rgba(11,29,54,0.06)]` — clone `AccountWithoutProfile` geometry.
- No AppShell, no clinic nav, no patient links.
- Single secondary `Button` fullWidth: Sair.

### 3. Pedido recusado

- Same card geometry as (2). Error icon well. Secondary fullWidth: Sair e voltar ao login.

### 4. Equipe

- Inside `AppShell`. `section.mx-auto.w-full.max-w-7xl` + `PageHeader` (same as `PatientsPage`).
- **Code card:** `rounded-2xl border border-line bg-surface p-4 md:p-6`. Code displayed at 20px/600, `tracking-widest`, `font-sans` (no new monospace font), 8 characters grouped as `XXXX XXXX` for reading only — clipboard writes the raw 8-char code.
- **Pendentes:** stacked cards on mobile (`rounded-2xl border border-line bg-surface p-4`); table optional from `md`. Each row: nome (14px/600), e-mail (12px muted), `Badge` “Pendente” tone `info`, actions Aceitar (`Button` secondary) + Recusar (`Button` ghost, `text-error` on the label only).
- **Ativos:** `DataTable` with columns Nome, E-mail, Status (`Badge` “Na equipe”). Empty uses DataTable `emptyTitle` / `emptyDescription` from the copy table.
- Loading: forest-border spinner in a `min-h-48` surface, same as PatientsPage.
- Recusar opens `ConfirmDialog` `tone="danger"`. Aceitar is immediate (no dialog).

### 5. Navegação

- Sidebar item **Equipe** path `/equipe`, icon `UserPlus` (lucide). Do **not** reuse `Users` — that icon is already Pacientes.
- Visible **only** when `account_type === 'empresa'` and `isAuthenticated`.
- Do **not** add Equipe to `mobileNavItems` (bottom bar stays 4 items). Mobile reaches Equipe via the hamburger drawer, which already renders `navigationItems`.
- AppShell footer role label: replace bakery `role` map with `account_type` labels — Autônomo / Empresa / Fisioterapeuta.

### 6. Pacientes em consulta (empresa)

- List: if the viewer is empresa and `created_by !== auth.uid()`, show a second line `Ficha de {nome}` at 12px muted.
- Ficha: banner `rounded-2xl border border-line bg-accent-soft px-4 py-3 text-sm text-forest` above tabs.
- `canWritePatient === false`: hide edit/delete/create controls; keep tab navigation and read-only fields. Do not show disabled buttons that look tappable.

## Interaction Contract

| Action | Behavior |
|--------|----------|
| Change tipo away from fisio | Unmount join-code field; clear `joinCode` value and errors |
| Submit cadastro fisio | Client Zod first; then `lookup_organization_by_code`; on fail stay on form with alert; on success `signUp` |
| Pending session visits `/` or `/cadastro` | Redirect to `/aguardando` |
| Pending session visits clinic routes | Redirect to `/aguardando` |
| Autônomo/fisio visits `/equipe` | Redirect `/pacientes` |
| Copiar código | `navigator.clipboard.writeText(rawCode)` then `toast('Código copiado')` |
| Aceitar | Call decide RPC; optimistic remove from pendentes + appear in ativos; toast |
| Recusar | ConfirmDialog → RPC → remove from pendentes; toast |
| Empresa abre ficha de fisio | Read-only banner; writes hidden |
| Autônomo | No Equipe item, no `/equipe` |

Focus: first invalid field on submit. Join-code input uses `aria-invalid` and existing Input error `role="alert"`. ConfirmDialog title is the accessible name of the danger action.

Reduced motion: inherit existing `prefers-reduced-motion` rules; do not add new page animations beyond existing `dash-in` on `/equipe` header/cards.
