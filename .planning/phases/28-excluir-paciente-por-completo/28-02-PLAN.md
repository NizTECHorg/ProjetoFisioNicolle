Contrato SQL (do plano 28-01; nomes exatos):
- `supabase.rpc('delete_patient_full', { p_patient_id: patientId })` → void; erro 42501 se não pode escrever ou paciente não existe
- `supabase.rpc('finish_patient_deletion', { p_patient_id: patientId })` → boolean (true = tombstone apagado, pasta vazia)
- `supabase.rpc('list_pending_patient_file_cleanups')` → `string[]` (UUIDs; PostgREST devolve array de uuid para `setof uuid`)
- Após a RPC, `storage.from(bucket).list(patientId, ...)` e `.remove(paths)` funcionam para o autor nos 3 buckets (policies de limpeza)

supabase-js (node_modules/@supabase/storage-js/dist/index.d.cts):
- `list(path?: string, options?: { limit?: number; offset?: number; sortBy?: ...; search?: string }) => Promise<{ data: FileObject[]; error: null } | { data: null; error: StorageError }>`; `limit` padrão 100
- `FileObject { name: string; id: string | null; ... }` — `id === null` é pseudo-pasta
- `remove(paths: string[]) => Promise<{ data: FileObject[]; error: null } | { data: null; error: StorageError }>` — RLS negada devolve `data: []` sem erro

- `import { supabase } from '@/lib/supabase/client'` (cliente sem genérico; `rpc` aceita qualquer nome)
