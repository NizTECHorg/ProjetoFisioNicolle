google-calendar-connect:
- Body: { refreshToken: string, accessToken?: string, googleEmail?: string, expiresAt?: string }
- Upsert google_calendar_secrets with service_role (refresh_token required)
- Upsert google_calendar_connections (google_email, connected_at) for auth.uid()
- Response JSON must NOT include refreshToken
- If refreshToken missing → 400 with Portuguese-safe code vault_missing

google-calendar-export:
- Body: { fromIso: string, toIso: string } (validate non-empty)
- Load secrets for auth.uid() via service_role; if missing → 401 needs_reconnect
- Refresh access_token via https://oauth2.googleapis.com/token using Deno.env GOOGLE_CLIENT_ID + GOOGLE_CLIENT_SECRET (never hardcode)
- Create user-scoped client with caller JWT; SELECT sessions in [fromIso, toIso) joining patient name/code/type/place/status the same fields CalendarSession needs
- For each session: if link exists PATCH /calendars/primary/events/{id} else POST insert; upsert google_calendar_session_links
- Use _shared/mapSessionToGoogleEvent (same rules as client mapper: 60 min, America/Sao_Paulo, D-08 allow-list)
- Return { exportedCount, failedCount } — never return tokens
- On Google 401/403 after refresh fail → 401 needs_reconnect

google-calendar-disconnect:
- Load refresh_token via service_role; best-effort POST revoke to Google revoke endpoint
- DELETE secrets + connections + optionally session_links for auth.uid()
- Response ok without tokens

Shared refresh helper may live in _shared/googleToken.ts if it keeps files small.

Do not call Google from the SPA. Prefer EF-only so page CSP may stay unchanged.
