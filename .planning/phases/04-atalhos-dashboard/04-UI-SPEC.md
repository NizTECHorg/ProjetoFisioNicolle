# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** No dashboard (`/painel`), o profissional inicia uma evolução ou uma avaliação sem abrir a ficha primeiro. Escolhe o paciente, cai no formulário já existente, e depois de salvar permanece no painel.

**Sources:** tokens from `src/index.css`; chrome from `PageHeader`, `Button`, `Modal`, `Input`, `Select`, `PatientAvatar`, `ToastViewport`; product copy from `04-CONTEXT.md` (D-01–D-04); design system reused from `03-UI-SPEC.md` (approved). Do not invent a new kit.

Reuse Phase 3 spacing, type, and color. New screens this phase: dashboard header actions, patient-picker `Modal`, create-only overlay wrapping the existing session/evaluation editors.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 3:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside header buttons (`gap-2` already on `Button`) |
| sm | 8px | Label-to-control gap (`space-y-2` on Input/Select); picker row inner gap to avatar; header CTA cluster |
| md | 16px | Default padding inside picker rows (`p-4`); toast inner padding (`px-4 py-3`) |
| lg | 24px | Modal inner padding (`p-6` already on `Modal`); gap between header title block and actions on stacked mobile |
| xl | 32px | Unused this phase |
| 2xl | 48px | Unused this phase |
| 3xl | 64px | Unused this phase |

Exceptions:

- Icon-only Modal close and picker rows: minimum hit area **44×44px**. Do not ship a 16px tap target.
- Existing `Button` padding (`px-6 py-3.5`) and `Input`/`Select` (`px-4 py-3.5`) stay as implemented.
- Do not change dashboard card gaps (`gap-4` / `lg:gap-3`) or replace the four metric cards. Dashboard `lg:gap-3` (12px) is existing chrome — out of scope. New spacing this phase uses only the table above.

## Typography

Exactly four sizes and two weights for **new** copy in this phase (same contract as Phase 3):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px (`text-sm`) | 400 | 1.5 |
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Heading | 20px (`text-xl`) | 600 | 1.2 |
| Display | 30px (`text-3xl`) | 600 | 1.2 |

Hints, inline errors, toast dismiss, and muted picker meta stay at **12px** (`text-xs`) because `Input`/`Select`/`ToastViewport` already render that size — do not invent a fifth size; do not change those components.

Existing chrome exceptions (do not restyle):

- `PageHeader` title remains `text-3xl` / `sm:text-4xl` / `lg:text-[2.125rem]` at weight 600. Dashboard title stays **Dashboard**.
- `Modal` title remains `text-lg` / 600 (`Nova sessão`, picker titles).
- `Input`/`Select` labels remain `text-sm font-medium` (500) inside those components.
- Dashboard metric numbers stay `text-5xl` / `lg:text-4xl` — out of scope; do not retune.

Header button labels use the existing `Button` type: 14px / 600.

Toast **Ver ficha** uses 14px / 600 (`text-sm font-semibold`), same weight as `Button` labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f3f5f8` (`canvas`) | Dashboard page background; Modal backdrop stays `bg-forest/40` |
| Secondary (30%) | `#ffffff` (`surface`) + `#0b1d36` (`forest`) | Overlay dialogs, picker rows, primary header button, toast success text |
| Accent (10%) | `#2f7dff` (`accent`) | Reserved list below — never body text or primary buttons |
| Destructive | `#dc4a4a` (`error`) | Save/load error toast and inline form errors only |

Accent reserved for:

1. Focus ring on `Input`/`Select` (`focus:border-accent` + `focus:ring-accent/25`) — already in those components
2. Empty-picker icon well (`bg-accent-soft` / `text-accent`) — clone `/equipe` empty geometry
3. Success/info toast surface (`bg-accent-soft` + `border-success/30`) — already in `ToastViewport`

Accent is **not** for: primary `Button` (stays `bg-forest`), **Nova avaliação** (secondary `Button`), **Ver ficha** (forest text on the toast), page title, body copy, or the four dashboard metric cards.

**Focal point:** **Nova evolução** is the visual anchor — `Button` primary in the `PageHeader` action slot. **Nova avaliação** is secondary (`Button` secondary, same slot, after the primary). The four metric cards stay supporting chrome; do not restyle, recolor, or enlarge them this phase.

Do not recolor dashboard stat cards, activity chart, or carteira this phase.

### Toasts (D-01 / D-03)

One toast per successful save. If the shared mutation hook already toasts, attach the action to **that** toast — do not stack a second banner.

| Event | Message | Tone | Action |
|-------|---------|------|--------|
| Evolution/session saved | Sessão salva | success | **Ver ficha** → `/pacientes/:id?aba=evolucoes` |
| Evaluation saved | Avaliação salva | success | **Ver ficha** → `/pacientes/:id?aba=avaliacao` |
| Save failed | **Não foi possível salvar. Verifique os campos e tente de novo.** | error | none — form stays open |
| Picker load failed | toast optional; prefer in-modal error article | error | none |

**Ver ficha** is a text button/link inside the same toast row as the message, label exactly **Ver ficha**. Click navigates and dismisses the toast. Stay on `/painel` unless the user clicks it (D-01).

**Voltar ao dashboard** / Escape / backdrop / X: close the entire overlay, return to `/painel`, **no toast** (D-02). Do not reopen the picker.

## Screens

### 1. Dashboard header actions

- Stay on `DashboardPage` inside `AppShell`. `section.mx-auto.w-full.max-w-7xl` unchanged.
- Pass `action` to existing `PageHeader`:
  - Cluster: `flex flex-col gap-2 sm:flex-row sm:flex-wrap` (8px).
  - **Nova evolução**: visual anchor — `Button` primary, `<Plus size={16} />`.
  - **Nova avaliação**: `Button` secondary, `<Plus size={16} />`, after the primary.
- Visible for `autonomo`, `empresa`, and active `fisioterapeuta` (anyone who can see `/painel`).
- Four metric cards are supporting only. Do **not** replace, restyle, enlarge, or insert between them.
- Do **not** add Equipe / Financeiro chrome.

### 2. Patient picker (`Modal`, not `wide`)

- Opens on `/painel` without navigating away. One overlay at a time.
- `Modal` default width (`max-w-lg`), existing z-index `z-[70]`. The close **X** button has `aria-label="Fechar"` (not only the backdrop).
- Body:
  1. If patients query loading: forest-border spinner in `min-h-32` (same geometry as ficha panels).
  2. If error: `article` `rounded-2xl border border-error/20 bg-error/5 px-6 py-8 text-sm text-error` with the error copy.
  3. If zero **writable** patients (`canWritePatient === true` only): empty card — icon well 48×48 `rounded-2xl bg-accent-soft text-accent` with `Users` (lucide) 22px; heading 14px/600; body 14px/400 muted; **Ir para pacientes**.
  4. Else: optional search + list.
- Search `Input` appears when writable count **≥ 8**. Filter by name, case-insensitive. Hidden below that threshold.
- List: stacked buttons `w-full rounded-2xl border border-line bg-surface p-4`, `min-h-11`, hover `hover:bg-canvas`. Row = `PatientAvatar` + name. Clicking a row **immediately** opens the matching editor (no Continuar).
- Empresa: omit teammate patients. Do not render disabled rows.

### 3. Evolution editor overlay

- After a patient is chosen from **Nova evolução**, replace the picker with the existing **Nova sessão** form (`PatientEvolutionsPanel` create `Modal`, `wide`).
- Mount create-only: `canWrite={true}` for the chosen patient; do not render the sessão list, pencil, or trash.
- **Voltar ao dashboard** / X / backdrop / Escape → close **all** shortcut UI; stay on `/painel` (D-02). Never pop back to the picker. Modal X must have `aria-label="Fechar"`.
- **Salvar sessão** success → close overlay, stay on `/painel`, one success toast with **Ver ficha** (D-01, D-03). Save error → overlay stays open; toast **Não foi possível salvar. Verifique os campos e tente de novo.**

### 4. Evaluation editor overlay

- After a patient is chosen from **Nova avaliação**, show the existing **Nova avaliação** fields inside `Modal` `wide` (the ficha currently inlines this form; the dashboard must overlay it so the user never leaves `/painel`).
- Create-only: hide evaluation list, Inicial/Posterior chips, PDF import, edit/delete.
- Same close rules as Screen 3 (**Voltar ao dashboard**). Submit label is **Salvar avaliação**. **Ver ficha** uses `?aba=avaliacao`.

### 5. Success toast with action

- Extend `ToastItem` with optional `action?: { label: string; href: string }` (or equivalent onClick + href). Do not add a second notification library.
- Layout: message (14px/400) on the left; **Ver ficha** (14px/600 `text-forest`) then existing **Fechar** (12px, opacity 60).
- When `action` is present, auto-dismiss at **6000ms** (default; existing toasts without action stay 4200ms) so the link is tappable.
- `role="status"` stays. **Ver ficha** is a `Link` / `<a>` (keyboard reachable). Toast viewport stays `z-[80]` above Modal.

## Interaction Contract

| Action | Behavior |
|--------|----------|
| Click Nova evolução / Nova avaliação | Open picker overlay on `/painel`. URL stays `/painel`. |
| Click patient row | Close picker; open the matching create editor for that id. |
| Empty **Ir para pacientes** | Close overlay; navigate to `/pacientes`. |
| Cancel / X / backdrop / Escape on picker | Close overlay; stay on `/painel`; no toast. Modal X: `aria-label="Fechar"`. |
| **Voltar ao dashboard** / X / backdrop / Escape on editor | Close **entire** shortcut (not back to picker); stay on `/painel`; no toast (D-02). |
| **Salvar sessão** / **Salvar avaliação** success | Close overlay; stay on `/painel`; one success toast + **Ver ficha** (D-01, D-03). |
| Save error | Editor stays open; toast **Não foi possível salvar. Verifique os campos e tente de novo.**; no navigation. |
| Click **Ver ficha** | Navigate to `/pacientes/:id?aba=evolucoes` or `?aba=avaliacao`; dismiss toast. |
| Want another record | Click the dashboard shortcut again (D-04). |
| Empresa / teammate ficha | Not listed in picker. `canWritePatient` is UX filter; RLS remains authority. |
| Hide vs disable | Hide write-only controls that the shortcut must not offer (lists, delete, PDF). Do not show disabled tappable buttons (Phase 3 D-07). |

Focus: when the picker opens, focus the search `Input` if visible, otherwise the first patient row. Existing Modal Escape handling is enough; do not add a new focus-trap library.

Reduced motion: inherit existing `prefers-reduced-motion` rules. Do not add overlay enter/exit animation beyond the current Modal (none). Header may keep `dash-in`.
