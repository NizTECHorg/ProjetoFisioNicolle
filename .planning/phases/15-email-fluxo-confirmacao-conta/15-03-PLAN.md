<objective>
Replace the broken e-mail CTA and correct the operator runbook so the confirmation link points at Supabase's own verify endpoint and lands back on the production origin.

Purpose: the shipped template builds its link from `{{ .SiteURL }}` plus a `token_hash` the SPA has to redeem in JavaScript. That is the direct cause of both reported bugs — the Dashboard Site URL is still a dev origin (bug 1), and a link that only confirms after the SPA boots confirms nothing when the page cannot load on the phone (bug 2). A bare `{{ .ConfirmationURL }}` is verified server-side by GoTrue before any redirect.
Output: Both Fluxo HTML templates rewritten, and `docs/ops/auth-email-smtp.md` corrected for templates, URL configuration, the Vercel build variable, the two bugs, and the REQ-27 UAT gate.
</objective>

<interfaces>
Facts the executor needs (no exploration required):

- GoTrue renders `{{ .ConfirmationURL }}` as `{SUPABASE_URL}/auth/v1/verify?token=...&type=signup&redirect_to={emailRedirectTo}`. The host is the Supabase project, not the Dashboard Site URL, so the CTA host stops depending on Dashboard state.
- GoTrue marks `email_confirmed_at` while serving that request, before it issues the redirect. That is what makes the account usable with e-mail + password even if the browser then fails to load the SPA.
- `redirect_to` is `emailRedirectTo` when that value is on the Dashboard Redirect URLs allow-list; otherwise GoTrue falls back to the Site URL. Plan 15-02 pins `emailRedirectTo` to `https://fluxofisio.vercel.app/auth/confirm`, so both Site URL and the allow-list must carry the same origin for the fallback to stay safe.
- Go templates are case-sensitive: `{{ .ConfirmationUrl }}` renders empty. Query parameters must not be appended to `{{ .ConfirmationURL }}` — GoTrue builds the whole URL.
- Existing brand tokens from `src/index.css`: forest `#0b1d36`, ink `#102038`, muted `#5a6b80`. E-mail HTML uses web-safe fonts only (Arial/Helvetica).
- `src/config/env.ts` (after plan 15-02) resolves `env.appUrl` from `PRODUCTION_APP_URL = https://fluxofisio.vercel.app`, accepting a `VITE_APP_URL` override only when it is https and non-local. A stale `VITE_APP_URL` in the Vercel project would therefore be ignored unless it is an https non-local origin — the runbook still has the operator delete any non-production value.
- The repo deploys as an SPA with `vercel.json` rewriting `/(.*)` to `/index.html`, so `/auth/confirm` resolves on the production host. No deploy-config change is needed.

| Dashboard Redirect URLs allow-list → GoTrue `redirect_to` | The allow-list is the server-side control over where an authenticated redirect may land |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
