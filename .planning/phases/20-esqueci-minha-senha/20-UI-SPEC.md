# Phase 20 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** No login, a pessoa que não lembra a senha pede um e-mail de redefinição (marca Fluxo já existente). O link abre o app em `/auth/confirm` para gravar uma senha nova. Depois do sucesso, só a senha nova entra. A troca logada em Minha conta permanece intacta.

**Sources:** REQ-31 in `REQUIREMENTS.md`; locked scope + copy recommendations in `20-RESEARCH.md` (no CONTEXT.md — discuss-phase skipped); auth chrome in `AuthLayout`, `LoginPage`, `RegisterPage`, `AuthConfirmPage`; tokens in `src/index.css`; password field patterns from `18-UI-SPEC.md` (labels, hint, show/hide) — **do not merge** the logged-in `changePassword` / `current_password` wall into this flow.

**Do not restyle** `AuthLayout`, `Button`, `Input`, or `ToastViewport`. Do **not** change `flowType`. Do **not** touch `/conta` password card, `changePassword`, or Phase 18 copy. Do **not** add shadcn, OTP UI, a second SMTP template, or localhost redirects.

| Body | 14px (`text-sm`) | 400 | 1.5 |

- `AuthLayout` page title remains `text-3xl font-semibold` (Display role via layout). Titles this phase: **Esqueci minha senha** (request), **Nova senha** (recovery form), signup confirm keeps **Confirmar e-mail**.

- `Input` labels remain `text-sm font-medium` (500) inside that component. Do not add a third weight on new elements outside `Input`.
- `Button` labels stay 14px / 600.
- Marketing aside remains `font-display text-5xl`.

**Focal point:** the e-mail field on `/esqueci-senha`; the **Nova senha** field on the recovery form.

## Copywriting Contract

All user-facing strings in Portuguese (pt-BR). No Submit, OK, Save, Cancel, Forgot password, or Reset on new chrome. No English, SQL, Auth error codes, or SMTP jargon in toasts.

| Element | Copy |
|---------|------|
| Primary CTA | **Enviar link** on `/esqueci-senha`. **Salvar nova senha** on the recovery form. |
| Empty state heading | N/A — guest forms always show fields; no data list. After a successful request, the heading stays **Esqueci minha senha** and the body becomes the anti-enumeration success (below). |
| Empty state body | N/A as a list empty state. Post-submit success body: **Se existir uma conta com este e-mail, enviamos um link para redefinir a senha.** |
| Error state | **Não foi possível enviar o link. Tente de novo.** (transport / generic failure on request). Recovery write failure: **Não foi possível salvar a nova senha. Tente de novo.** |
| Destructive confirmation | none — this phase has no destructive actions |

### Login (`/`)

| Element | Copy |
|---------|------|
| Link label | **Esqueci minha senha** |
| Placement | Under the password field / **Mostrar senha** block, before the **Entrar** button — or immediately under **Entrar** as a secondary text link. Prefer **under the password block, above Entrar**, so the path is visible before submit. |
| Style | `text-xs text-muted hover:text-forest` (match **Mostrar senha**). `Link` to `/esqueci-senha`. Not a second primary button. |
| Must not | Link to `/conta`, open OTP, or call `resetPasswordForEmail` from the login submit. |

Footer **Criar conta** link stays unchanged.

### Pedir e-mail (`/esqueci-senha` — GuestRoute)

| Element | Copy |
|---------|------|
| AuthLayout title | **Esqueci minha senha** |
| AuthLayout subtitle | **Informe o e-mail da conta. Enviamos um link para criar uma senha nova.** |
| Field label | **E-mail** |
| Placeholder | `seu@email.com` |
| Primary CTA | **Enviar link** (`Button` `fullWidth`; loading label stays the component’s **Aguarde...**) |
| Footer | **Lembrou a senha?** + link **Entrar** → `/` (`font-medium text-forest hover:text-forest-mid`) |
| Success (anti-enumeration) | Same UI whether the address exists or not. Prefer replacing the form with centered Body text: **Se existir uma conta com este e-mail, enviamos um link para redefinir a senha.** Optional supporting line: **Confira também a pasta de spam.** Keep a text link **Voltar ao login** → `/`. Do **not** toast a different message for unknown e-mail. Do **not** say “e-mail não cadastrado” or “conta não encontrada”. |
| Inline empty e-mail | Existing schema message (same as login) — do not invent a second string. |
| Rate limit | Toast **Muitas tentativas. Aguarde e tente novamente mais tarde.** |
| Network / SMTP / Auth error | Toast **Não foi possível enviar o link. Tente de novo.** Do not surface “confirmação de cadastro” wording from signup `mapAuthError` SMTP branches — recovery-specific mapping when calling reset. |

Never probe `profiles` / `auth.users` before submit. Never show success for one path and error for “user missing.”

### Confirmação de cadastro (`/auth/confirm` — signup path, unchanged)

Keep existing copy and behavior when the session is **not** recovery:

| Element | Copy |
|---------|------|
| Title / subtitle | **Confirmar e-mail** / **Validando o link enviado para sua caixa de entrada** |
| Working | **Confirmando seu e-mail…** |
| Success | **E-mail confirmado. Você já pode entrar na Fluxo.** + toast **E-mail confirmado com sucesso.** + redirect `/` |
| Consumed / expired (signup) | Existing signup wording (cadastro / entrar) — do not replace with recovery copy |
| Error CTA | **Ir para o login** |

### Nova senha (recovery branch on `/auth/confirm`)

Detect recovery (`type=recovery` and/or `PASSWORD_RECOVERY`) **before** the signup success path. Do not auto-navigate into the clinic. Do not show **E-mail confirmado**.

| Element | Copy |
|---------|------|
| AuthLayout title | **Nova senha** |
| AuthLayout subtitle | **Escolha uma senha nova para entrar na Fluxo.** |
| Working (before form) | Keep spinner; Body: **Validando o link…** (not “Confirmando seu e-mail…”) |
| Field 1 | **Nova senha** — `autoComplete="new-password"`, placeholder `••••••••••••`, hint **Mínimo 8 caracteres, com maiúscula, minúscula, número e caractere especial** |
| Field 2 | **Confirmar nova senha** — `autoComplete="new-password"`, placeholder `••••••••••••` |
| Show/hide | **Mostrar senhas** / **Ocultar senhas** — reveals both fields together (`text-xs text-muted hover:text-forest`) |
| Primary CTA | **Salvar nova senha** (`Button` `fullWidth`) |
| Must not show | **Senha atual**, OTP, e-mail field, or any Minha conta card chrome |

#### Validation & outcomes (recovery only)

| Situation | What the person sees | What must not happen |
|-----------|----------------------|----------------------|
| **Nova senha** empty | Inline **Informe a nova senha.** | No `updateUser` |
| **Confirmar nova senha** empty | Inline **Confirme a nova senha.** | No `updateUser` |
| Confirmation mismatch | Inline **As senhas não coincidem.** on **Confirmar nova senha** | No `updateUser` |
| Fails `passwordSchema` | Same specific schema lines as cadastro / Phase 18 | No `updateUser`; do not invent a generic “requisitos de segurança” line |
| Save succeeds | Toast **Senha atualizada.** Then `signOut` and navigate to `/` (login). Optional brief Body before redirect: **Senha atualizada. Entre com a senha nova.** | Do not enter clinic on the recovery session. Do not call `changePassword`. Do not send `current_password`. |
| Link invalid / incomplete (recovery) | **Link inválido ou incompleto. Peça um novo link em Esqueci minha senha.** + **Ir para o login** | Do not use “Cadastre-se de novo…” |
| Link already used / expired (recovery) | **Este link já foi usado ou expirou. Peça um novo link em Esqueci minha senha.** + **Ir para o login** | Do not use signup “conta já confirmada / novo cadastro” wording |
| Rate limit | Toast **Muitas tentativas. Aguarde e tente novamente mais tarde.** | Password unchanged |
| Other Auth/network failure | Toast **Não foi possível salvar a nova senha. Tente de novo.** | Password unchanged; stay on form when session still valid |

## Interaction Contract

```text
Login —[Esqueci minha senha]→ /esqueci-senha
  → Enviar link → identical success copy (anti-enumeration)
  → e-mail Fluxo (Dashboard template) → /auth/v1/verify?type=recovery
  → /auth/confirm (recovery) → Nova senha form
  → Salvar nova senha → updateUser({ password }) → signOut → Login
```

| Rule | Contract |
|------|----------|
| Entry | Clear text path on login; GuestRoute owns `/esqueci-senha` |
| Landing | Recovery always lands on `/auth/confirm` (Dashboard redirect unchanged) |
| Branch | Recovery ≠ signup confirm copy/navigation |
| Password write | `updateUser({ password })` only — no `current_password`, no `changePassword` |
| After success | `signOut` then login so the person enters with the new password |
| Minha conta | Untouched |
