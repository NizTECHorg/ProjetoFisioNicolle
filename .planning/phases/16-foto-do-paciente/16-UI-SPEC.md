# Phase 16 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** Na ficha e na lista de pacientes, a foto substitui as iniciais. O hover mostra uma câmera e o clique abre a escolha de um arquivo PNG ou JPEG. Sem arquivo, as iniciais e `photo_tone` continuam. Quadro, agenda, painel e o atalho clínico só mostram a mesma foto.

**Sources:** D-01–D-04 and the phase boundary in `16-CONTEXT.md`; screen split, overlay, copy split from the gallery, and remove-on-ficha in `16-RESEARCH.md`; tokens in `src/index.css`; avatar diameters in `PatientAvatar.tsx`; spacing, type, and color reused from `07-UI-SPEC.md` (approved).

**Do not restyle** `Button`, `Modal`, `ConfirmDialog`, `ToastViewport`, `PageHeader`, AppShell, or the aba Imagens. Do **not** add shadcn, a crop modal, a camera capture sheet, or `clsx`. Do **not** design the clinical gallery, live capture, WebP, or HEIC.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 3 / Phase 5 / Phase 6 / Phase 7:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between the status pill and **Remover foto** when the name row wraps (`gap-1` is forbidden; use `gap-2` minimum between those two controls, which is sm) |
| sm | 8px | Name-row wrap gap stays the existing `gap-2`; do not add a tighter gap |
| md | 16px | Unused for new chrome. Do not change list card padding `p-4` |
| lg | 24px | Unused this phase |
| xl | 32px | Unused this phase |
| 2xl | 48px | Unused this phase |
| 3xl | 64px | Unused this phase |

Exceptions:

- Keep the existing avatar diameters. They are the hit target, not a new spacing token: `sm` 36×36 (display only), `md` 40×40 (list, painel, agenda, atalho), ficha `lg` 56×56 below `sm` and 64×64 from `sm` up (`!h-14 !w-14` / `sm:!h-16 !w-16`). Do not grow the circle to 44px.
- The camera glyph is decorative and `pointer-events-none`. Do not add a separate 44×44 camera button beside or over a second hotspot. The `<label>` is the full circle.
- **Remover foto** (ficha only) is a text control with minimum hit area **44×44px** (`min-h-11`, horizontal padding `px-2`). It sits in the name row, not under the circle, so column 1 of the header grid does not widen.
- Do not change the header grid `gap-x-3 sm:gap-x-4` or the list row `gap-3`. Those existing gaps stay. New spacing uses only the scale above.
- Overlay is `inset-0` on the circle. No extra margin.

## Typography

Exactly four sizes and two weights for **new** copy in this phase (same contract as Phase 7):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px (`text-sm`) | 400 | 1.5 |
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Heading | 20px (`text-xl`) | 600 | 1.2 |
| Display | 30px (`text-3xl`) | 600 | 1.2 |

Display and Heading are **unused** this phase. Do not invent a fifth size and do not restyle the patient name.

**Remover foto** is 12px (`text-xs`) / 400 / line-height 1.5. That size already exists on pills, meta lines, and toasts — it is not a new role. ConfirmDialog title stays the existing Modal `text-lg` / 600. Confirm and cancel labels stay the existing `Button` chrome (14px / 600).

Initials inside the circle stay `font-semibold text-white` (weight 600) at the size already on `PatientAvatar` (`text-xs` on `sm`/`md`, `text-lg` on `lg`, with the header overrides `!text-base` / `sm:!text-lg`). Do not change initials tracking or color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f3f5f8` (`canvas`) | Page background behind the list and the ficha. Unchanged. |
| Secondary (30%) | `#ffffff` (`surface`) + `#0b1d36` (`forest`) | List cards and the ficha header stay surface/ink. The hover scrim is `bg-forest/55` with a white `Camera`. |
| Accent (10%) | `#2f7dff` (`accent`) | Reserved list below only |
| Destructive | `#dc4a4a` (`error`) | **Remover foto** confirm button only (`ConfirmDialog` `tone="danger"`). The trigger label uses `text-muted` and `hover:text-error`. |

Accent reserved for:

1. Keyboard focus ring on the photo `<label>` — existing `:focus-visible` rule in `src/index.css` (`outline-2 outline-offset-2 outline-accent`). Do not add a second ring color.
2. Success toast surface (`bg-accent-soft` + `border-success/30`) — already in `ToastViewport`. Do not restyle it.

Accent is **not** for: the camera glyph, the scrim, the circle fill (`photo_tone` via `avatarColor`), **Remover foto**, body copy, or the consult banner. The circle fill stays `photo_tone` behind a transparent PNG (D-01). Do not flatten the PNG onto white or black.

**Focal point:** the circle. On an editable avatar the camera scrim is the affordance. **Remover foto** is secondary and only on the ficha when a photo is already saved.

Do not recolor AppShell, ficha tabs, aba Imagens, kanban cards, or agenda cards.

## Copywriting Contract

All user-facing strings in Portuguese (pt-BR). No generic Submit / OK / Save / Cancel on new chrome. No English, SQL, MIME enums, or byte counts in toasts. No native `title` tooltip on the circle.

| Element | Copy |
|---------|------|
| Primary CTA | **Escolher foto** — accessible name of the file control when `photoUrl` is null. When a photo is already showing, the same control is named **Trocar foto**. There is no visible button label on the circle. |
| Empty state heading | Sem título. O círculo mostra as iniciais em branco sobre `photo_tone`. |
| Empty state body | Sem frase. Não escrever “Sem foto”, “Adicionar foto” ou “Nenhuma foto” debaixo do círculo. |
| Error state | Envie PNG ou JPEG. |
| Destructive confirmation | Remover foto: “A foto sai da ficha e das listas. As iniciais voltam.” Confirm label: **Remover foto**. Cancel: **Voltar**. |

Append the patient name in the accessible name so a list of circles is distinguishable: `Escolher foto de {name}`, `Trocar foto de {name}`, `Remover foto de {name}`. The visible patient name next to the circle is unchanged. The `<img>` uses `alt=""`.

### Onde a câmera existe

| Surface | Editable | Copy on the circle |
|---------|----------|--------------------|
| Ficha header (`PatientProfileHeader`, size `lg`) | Yes, if `canWrite` | Hover/foco: `Camera`. Clique: file picker. **Remover foto** na linha do nome só se já houver foto. |
| Lista de pacientes, cartão mobile e linha desktop (`PatientsPage`, size `md`) | Yes, if `canWritePatient` | Hover/foco: `Camera`. Clique: file picker. Sem **Remover foto**. |
| Quadro (`KanbanPage`, size `sm`) | No | Foto ou iniciais. Sem câmera, sem input. |
| Agenda (`CalendarPage`) | No | Foto ou iniciais. Sem câmera, sem input. |
| Painel, Próximas sessões (`DashboardPage`, size `md`) | No | Foto ou iniciais. Sem câmera, sem input. |
| Atalho clínico (`DashboardClinicalShortcut`) | No | Foto ou iniciais. Sem câmera, sem input. A linha continua sendo o botão de escolher o paciente. |

`!canWrite` unmounts `PatientPhotoControl`. Render `PatientAvatar` only. Do not disable the circle. The existing consult banner stays the only explanation: **Somente consulta — você vê a ficha, mas não pode alterar.** Do not add a second banner.

### Toasts e erros de arquivo

| Event | Message | Tone |
|-------|---------|------|
| Upload success | Foto atualizada. | success |
| Remove success | Foto removida. | success |
| Not PNG or JPEG (extension, empty `file.type`, magic bytes, WebP, HEIC, PDF, GIF, SVG) | Envie PNG ou JPEG. | error |
| Original file over 8 MB, before decode | A foto deve ter no máximo 8 MB. | error |
| Decode, crop, or save failure (including cropped blob over 2 MB) | Não foi possível salvar a foto. Tente de novo. | error |
| Remove failure | Não foi possível remover a foto. Tente de novo. | error |
| RLS / 42501 | Você não tem permissão para esta ação. | error |
| Picker dismissed with no file | No toast | — |
| Signed URL fails to paint | No toast. Fall back to initials on `photo_tone`. | — |

Do not reuse gallery copy. Forbidden in this phase: “Envie JPEG, PNG, WebP ou PDF”, “Fotos do iPhone”, “até 8 MB” as a helper under the circle, and any raw `error.message`. Permission text is the existing sentence above, not a new one.

## Screens

### 1. `PatientAvatar` (every current call site)

- Add optional `photoUrl: string | null`. Null or `''` keeps D-01: initials (or the `initials` prop) and `backgroundColor: avatarColor(tone)`.
- Add `overflow-hidden` to the circle so the image clips. Keep `rounded-full`.
- When `photoUrl` is set, render `<img src={photoUrl} alt="" className="h-full w-full object-cover" />` inside the same span. The tone remains the CSS background behind a transparent PNG.
- `onError` on the img: stop showing the img and render initials. Do not leave the browser broken-image icon.
- The component does not open a file dialog, does not render `Camera`, and does not know `canWrite`.

### 2. `PatientPhotoControl` (ficha + lista, writers only)

- A `<label className="group/photo relative inline-flex">` around `PatientAvatar`, plus a visually hidden file input.
- Use `group/photo`. Never a bare `group-hover`. The ficha header root already has `group` (the cadastro pencil uses it). A bare `group-hover` would show the camera while the pointer is on the name or the tabs.
- File input:

```html
<input type="file" accept="image/png,image/jpeg,.png,.jpg,.jpeg" className="sr-only" />
```

- Do not set `capture`. Do not set `multiple`. Do not use `accept="image/*"`.
- After `change`, set `input.value = ''` so the same file can be chosen again.
- Overlay: `pointer-events-none absolute inset-0 flex items-center justify-center rounded-full bg-forest/55 text-white opacity-0 group-hover/photo:opacity-100 group-focus-within/photo:opacity-100 [@media(hover:none)]:opacity-100 motion-reduce:transition-none`.
- Fine pointer: the scrim appears on hover and on keyboard focus inside the label (D-02 plus focus).
- Coarse pointer (`hover: none`): the scrim stays visible, because a phone has no hover. The label is still the hit target, so a tap opens the picker (D-03). The icon never captures the tap.
- `Camera` is `aria-hidden`. 16px on `md`, 20px on ficha `lg`. `stroke` default. White on the forest scrim.
- While the upload mutation is pending: `aria-busy="true"` on the label, ignore further `change` events, and replace the camera with the existing spinner (`h-4 w-4 animate-spin rounded-full border-2 border-white border-t-transparent`). Do not unmount the label and do not `disabled` it into a control that still looks tappable after the request ends.
- Accessible name on the input: **Escolher foto de {name}** or **Trocar foto de {name}**.

### 3. Ficha header

- Pass `photoUrl` into the header. When `canWrite`, render `PatientPhotoControl` in the avatar cell (size `lg`, keep the current `!h-14 !w-14` / `sm:!h-16 !w-16` classes). When `!canWrite`, render `PatientAvatar` with `photoUrl`.
- **Remover foto** renders only when `canWrite` and `photoUrl` is non-null. Place it in the existing name row (`flex-wrap items-center gap-2`), after the status pill. Classes: `inline-flex min-h-11 items-center px-2 text-xs text-muted hover:text-error`. Unmount it when there is no photo. Do not put it on the circle.
- Clicking **Remover foto** opens the existing `ConfirmDialog` (`tone="danger"`). It does not open the file picker.
- Confirm nulls the photo, then the circle returns to initials on every surface that already draws this patient. Toast **Foto removida.**
- **Voltar**, X, Escape, and backdrop close the dialog with no write and no toast. Cancel label is **Voltar** (override the default **Cancelar**).

### 4. Lista de pacientes

- Mobile: the row is a `<Link>` today. A `<label>` inside an `<a>` is invalid and the click navigates away. Move the card chrome (`rounded-2xl border border-line bg-surface p-4`) to a wrapper `<div className="flex items-center gap-3">`. The photo control is the first sibling. The `<Link>` is `min-w-0 flex-1` and contains the name and the meta line only.
- Desktop: the `<tr>` navigates on click and on Enter/Space. On the photo control, `stopPropagation` for `click` and `keydown` so choosing a file does not open the ficha. Do not remove the row click for the rest of the row.
- Both layouts use size `md`. No **Remover foto** on the list.
- Read-only rows keep today’s single `<Link>` / row click and a plain `PatientAvatar` with `photoUrl`.

### 5. Display-only surfaces

- Kanban, agenda, painel (Próximas sessões), and the clinical shortcut pass `photoUrl` into the existing `PatientAvatar` and stop there.
- Do not add `PatientPhotoControl` on a `draggable` kanban card or on a shortcut `<button>`. A camera on those surfaces is a bug.

### 6. What this phase does not draw

- No crop modal, no zoom slider, no “ajustar enquadramento”. The square crop happens before upload with no extra screen.
- No live camera, no `capture`, no second file button labeled Tirar foto.
- No upload entry on aba Imagens, and a saved avatar must not appear as a gallery tile.
- No WebP, HEIC, or PDF in the picker hint or in error copy.

## Interaction Contract

| Action | Behavior |
|--------|----------|
| No `photoUrl` | Initials on `photo_tone`. Editable circle still accepts a click. |
| Hover or keyboard focus on an editable circle | Forest scrim + white `Camera`. Read-only circles never show it. |
| Hover elsewhere on the ficha header | Camera stays hidden (`group/photo` only). |
| Click or tap the editable circle | Open the file picker. Do not navigate. On the list, the rest of the row still opens the ficha. |
| Coarse pointer | Camera stays visible on editable circles. Tap still opens the picker. |
| Pick PNG or JPEG | Center-crop with no editor UI. On success, toast **Foto atualizada.** Circle shows `object-cover`. Tone stays behind transparency. |
| Pick anything else, or a renamed WebP/HEIC | Do not upload. Toast **Envie PNG ou JPEG.** Circle unchanged. |
| File over 8 MB | Do not decode. Toast **A foto deve ter no máximo 8 MB.** |
| Save / crop / permission failure | Circle unchanged. Toast the matching row in the copy table. |
| Dismiss the picker | No toast, no navigation. |
| **Remover foto** on the ficha | ConfirmDialog. **Remover foto** confirms. **Voltar** cancels. Success: initials everywhere that avatar is drawn, toast **Foto removida.** |
| `!canWrite` | Photo if one exists, otherwise initials. No camera, no input, no **Remover foto**. |
| Hide vs disable | Never leave a disabled camera or a disabled **Remover foto** that still looks tappable. Unmount them. |

Focus: the file input stays in the accessibility tree via `sr-only` (do not `display: none` it). ConfirmDialog title **Remover foto** is the accessible name of that dialog. `:focus-visible` uses the existing accent outline.
