Contrato SQL (do plano 31-01; nomes exatos, chamados com o cliente service role):
- `admin.rpc('delete_account_data', { p_user_id: user.id })` → `data: { mode: 'data_owner' | 'org_owner' | 'org_therapist', patient_ids: string[] }`; erro → falha de banco (nada mudou; transação desfeita)
- `admin.rpc('finish_account_deletion', { p_user_id: user.id })` → boolean (best effort; o tombstone só tem UUIDs)

Contrato HTTP que este plano CRIA (o plano 31-03 consome):
- Request: `POST`, header `Authorization: Bearer <access_token>`, body JSON `{ confirm: 'EXCLUIR', password: string }`. Qualquer outro campo é ignorado.
- 200 `{ ok: true }`
- 400 `{ error: 'invalid_request', code: 'invalid_request' }` (confirm diferente de `EXCLUIR`, senha ausente/vazia/não-string, usuário sem e-mail)
- 401 `{ error: 'unauthorized', code: 'unauthorized' }` (sem Bearer ou token inválido)
- 401 `{ error: 'invalid_password', code: 'invalid_password' }`
- 429 `{ error: 'rate_limited', code: 'rate_limited' }` (GoTrue devolveu status 429 ou code `over_request_rate_limit`)
- 405 `{ error: 'method_not_allowed' }`
- 500 `{ error: 'delete_failed', code: 'delete_failed' }` (rpc ou deleteUser) / `{ error: 'storage_failed', code: 'storage_failed' }`

Helpers do projeto a copiar de supabase/functions/google-calendar-disconnect/index.ts (funções são self-contained, sem imports compartilhados): `corsHeaders`, `jsonResponse(body, status)`, `optionsResponse()`, `createServiceClient()` (`SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`, `persistSession:false, autoRefreshToken:false`), `createUserClient(authHeader)`, `requireUser(req)` (`getUser(token)`), `revokeGoogleToken(token)`. Import: `import { createClient, type SupabaseClient, type User } from 'npm:@supabase/supabase-js@2'`.

supabase-js storage: `admin.storage.from(bucket).list(folder, { limit: 100, offset: 0 })` → `{ data: FileObject[] | null, error }`; `FileObject.id === null` é pseudo-pasta; `remove(paths: string[])`.
Buckets: por paciente `patient-avatars`, `patient-images`, `patient-ai-reports` (`{patientId}/arquivo`); conta `account-avatars` (`{userId}/arquivo`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Edge Function | Corpo e headers são controlados pelo chamador (inclusive fora do app, com um JWT roubado) |
| Edge Function → Supabase (service role) | Bypassa RLS; só pode agir sobre o `user.id` validado |
| Edge Function → Browser (respostas) | Erros internos não podem vazar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-07 | Elevation of privilege (IDOR em id de outro usuário) | handler | mitigate | Id só de `requireUser` → `getUser(token)`; corpo lido apenas para `confirm` e `password`; contrato proíbe `body.userId/user_id/id/email` e exige `p_user_id: user.id` e `deleteUser(user.id)` |
| T-31-08 | Spoofing (sessão roubada / falta de reautenticação) | reverificação | mitigate | `signInWithPassword` com o e-mail do JWT num cliente anon efêmero antes de qualquer escrita; `confirm === 'EXCLUIR'` checado no servidor; signOut local do probe |
| T-31-09 | Information disclosure (service role) | `createServiceClient` | mitigate | Chave só de `Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')`; nada no cliente (contrato do plano 31-03 proíbe `SERVICE_ROLE` em `src/`) |
| T-31-10 | Denial of service / integridade (conta pela metade) | ordem dos passos | mitigate | Banco (transação) → storage → `deleteUser` por último; falha em qualquer passo após a RPC mantém login e tombstone, o retry é idempotente |
| T-31-11 | Denial of service (deleteUser bloqueado por storage owner) | storage | mitigate | SQL do 31-01 reatribui/limpa `owner`; aqui as pastas dos pacientes apagados e `account-avatars/{userId}` são esvaziadas antes do `deleteUser` |
| T-31-12 | Information disclosure (vazamento de erro) | `jsonResponse` | mitigate | Só codes fixos; contrato proíbe `error.message` em `jsonResponse`; logs só com UUID |
| T-31-13 | Spoofing (força bruta de senha pelo endpoint) | `signInWithPassword` | mitigate | Rate limit do GoTrue mapeado para 429 `rate_limited`; resposta genérica `invalid_password`; rate limit no cliente (31-03) |
| T-31-SC | Tampering | `npm:@supabase/supabase-js@2` | accept | Mesmo import das 4 funções existentes; nenhum pacote novo |
</threat_model>
