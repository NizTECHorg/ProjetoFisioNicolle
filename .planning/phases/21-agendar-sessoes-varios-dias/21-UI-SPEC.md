## Layout & Interaction Contract

### Ordem dos campos no modal (`<form className="space-y-4">`)

1. Paciente *(inalterado)*
2. Data *(inalterado; rótulo continua "Data")*
3. Horário *(inalterado)*
4. **Dias da semana** — chips `[LOCKED]` **(novo)**
5. **Repetir por quantas semanas** — campo numérico `[LOCKED]` **(substitui "Horário fixo")**
6. **Preview** — caixa de resumo `[LOCKED]` **(novo)**
7. Tipo *(inalterado)*
8. Sala *(inalterado)*
9. Botão "Agendar" *(mesmo botão; texto condicional abaixo)*

Dica de posição: a ajuda dinâmica que hoje fica no `hint` do campo "Horário fixo" é **removida** do `Input` e substituída pelo Preview (item 6), para não duplicar informação. O `hint` do campo de semanas passa a ser curto e fixo (ver Copywriting).

### 1. Chips de dias da semana `[LOCKED]`

- Container: grupo semântico `role="group"` com `aria-labelledby` apontando para o rótulo "Dias da semana".
- Layout: `grid grid-cols-7 gap-1` (7 colunas iguais, ordem **Seg → Dom**, Segunda primeiro como em `WEEKDAYS`).
- Cada chip: `<button type="button" aria-pressed={marcado}>`, classes base `min-h-11 rounded-xl text-sm font-medium transition` + estados de cor acima; foco visível `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent/25`.
- `aria-label` completo por chip (ex.: "Segunda-feira") para leitor de tela; texto visível abreviado ("Seg").
- Seleção múltipla: clique alterna marcado/desmarcado.
- **Estado inicial:** apenas o dia da semana da **data escolhida** marcado `[LOCKED]`. Segue a data enquanto o usuário não tocar em nenhum chip (comportamento `weekdaysTouched` da RESEARCH, Pattern 3). Depois do primeiro toque, a data passa a ser só o "início da série".
- **Mínimo de um dia `[LOCKED]`:** o último chip marcado **não desmarca** (clique é ignorado; `aria-disabled="true"` nesse chip enquanto for o único marcado; **sem** mudança visual de "desabilitado", para não parecer quebrado). A linha de ajuda do grupo explica a regra (Copywriting). Nunca existe série com zero dias → o botão "Agendar" não precisa de estado de erro para isso.
- Mapeamento: chips guardam o dia JS (`getDay()`: Seg=1 … Sáb=6, Dom=0); exibidos Seg→Dom (RESEARCH Pitfall 1).
- Sem atalhos nesta fase ("Dias úteis", "Todos"): não pedidos (fora de escopo).

### 2. Campo "Repetir por quantas semanas" `[LOCKED]`

- Mesmo componente `Input` já usado: `type="number"`, `min={1}`, `max={24}`, `inputMode="numeric"`, valor padrão `1`. Mesma normalização `clampWeeks` (vazio/0 → 1; > 24 → 24; decimais truncam).
- O número significa **quantas semanas os dias marcados se repetem**; o **mesmo horário** vale para todas as ocorrências `[LOCKED]`.
- Rótulo **não** pode ser "Horário fixo" `[LOCKED]`.
- Hint fixo (não dinâmico), `text-xs text-muted` via prop `hint`.

### 3. Preview `[LOCKED]`

- Elemento: `<p>` (ou `<div>`) com `role="status"` e `aria-live="polite"`, classes `rounded-2xl border border-accent/30 bg-accent-soft p-3 text-sm text-forest` (padrão existente na página).
- Atualiza ao mudar: data, horário, chips ou semanas.
- Total = (nº de dias marcados) × (semanas) — contado pelo helper `buildWeeklySeries(...).length`, **não** recalculado à mão, para ficar coerente com o que será gravado (inclui data inicial fora dos dias marcados).
- Mostra: total, composição "D dia(s) × S semana(s)", intervalo da 1ª à última data e o horário.
- Se o horário estiver vazio, omitir o trecho "às HH:mm" no preview (não prometer um horário que o usuário não digitou). No submit, horário vazio grava **09:00**: `Number('')` é `0`, então o default `hours = 9` não vale — `seriesStartAt` trata string vazia ou número inválido como 9h00.
- Formato de data no preview: `dd/MM` (pt-BR); incluir `/aaaa` apenas se a 1ª e a última data estiverem em anos diferentes.
- Caso de 1 sessão: sem composição nem intervalo, só a data.

### 4. Botão "Agendar"

- Mantém `Button type="submit" fullWidth`, `isLoading={create.isPending}`, `disabled={!patientId}`.
- Rótulo: `Agendar` quando total = 1; `Agendar N sessões` quando total > 1 (reforça o número antes de confirmar; N = mesmo valor do preview).

### Estados

| Estado | Comportamento |
|--------|---------------|
| Abrir modal ("Nova sessão") | Chips resetados: só o dia da data escolhida; semanas = 1; `weekdaysTouched = false`. O botão "Agendar sessão neste dia" também deve passar por `openComposer` para resetar (RESEARCH Pitfall 6) |
| Trocar a data (antes de tocar chips) | Chip marcado acompanha o novo dia da semana |
| Trocar a data (depois de tocar chips) | Chips permanecem; data = início da série |
| Data inicial fora dos dias marcados | Permitido (A3 da RESEARCH). Preview mostra o intervalo real, sem forçar a data inicial |
| Semanas digitadas fora de 1–24 | Preview e submit usam o valor normalizado (`clampWeeks`) |
| Enviando | `Button` com `isLoading` (existente); chips e campos continuam como hoje (sem novo overlay) |
| Sucesso | Modal fecha (existente); toast existente: "Sessão agendada" / "N sessões agendadas" — **não alterar** |
| Erro do servidor | Toast de erro já tratado por `onError` do hook; modal permanece aberto com os dados preenchidos. Como o insert é único e atômico, nenhuma sessão é criada em caso de falha |
| Sem paciente | "Agendar" desabilitado (existente) |
| Série longa (até 168) | Sem confirmação extra nem teto novo; o Preview e o rótulo do botão tornam a quantidade visível (A2 da RESEARCH) |

Layout responsivo: mobile e desktop usam a mesma grade de 7 colunas (largura útil do `Modal`, sem `wide`). Se a largura dos chips ficar apertada em 320px, o rótulo `text-sm` com 3 letras continua legível; não reduzir abaixo de `text-sm` nem trocar para scroll horizontal.

## Copywriting Contract

Todo texto em português do Brasil. Sem emojis. Sem jargão (evitar "ocorrência", "ciclo", "recorrência" na UI).

| Element | Copy |
|---------|------|
| Rótulo do grupo de chips | `Dias da semana` |
| Ajuda do grupo (`text-xs text-muted`) | `Marque um ou mais dias. Pelo menos um dia precisa ficar marcado.` |
| Chips (texto visível) | `Seg` · `Ter` · `Qua` · `Qui` · `Sex` · `Sáb` · `Dom` |
| Chips (`aria-label`) | `Segunda-feira` · `Terça-feira` · `Quarta-feira` · `Quinta-feira` · `Sexta-feira` · `Sábado` · `Domingo` |
| Rótulo do campo numérico | `Repetir por quantas semanas` |
| Hint do campo numérico | `Os dias marcados se repetem a cada semana, sempre no mesmo horário. De 1 a 24 semanas.` |
| Preview — 1 sessão | `Será criada 1 sessão agendada em {dd/MM}{, às HH:mm}.` |
| Preview — várias, 1 dia marcado | `Serão criadas {N} sessões agendadas ({S} semanas, 1 dia por semana), de {dd/MM} a {dd/MM}{, às HH:mm}.` |
| Preview — várias, vários dias | `Serão criadas {N} sessões agendadas ({D} dias × {S} semanas), de {dd/MM} a {dd/MM}{, às HH:mm}.` |
| Primary CTA | `Agendar` (1 sessão) / `Agendar {N} sessões` (várias) |
| Título do modal | `Nova sessão` (inalterado) |
| Empty state heading | not applicable — nenhuma lista nova; a seleção de dias nunca fica vazia (mínimo 1) |
| Empty state body | not applicable |
| Error state | Reutiliza o toast de erro existente (`onError`). Se for preciso texto novo: `Não foi possível agendar as sessões. Nenhuma foi criada. Tente novamente.` (reflete a atomicidade do insert) |
| Destructive confirmation | not applicable — fase **não** tem ação destrutiva (só cria sessões `agendada`) |

Notas de copy:
- Plural/singular obrigatório: `1 sessão` / `{N} sessões`; `1 semana` / `{S} semanas`; `1 dia` / `{D} dias`.
- `{, às HH:mm}` só aparece quando o campo Horário tem valor.
- Exemplo: sexta 02/10, Seg+Qua+Sáb, 2 semanas, 09:00 → `Serão criadas 6 sessões agendadas (3 dias × 2 semanas), de 03/10 a 14/10, às 09:00.` (bate com o protótipo da RESEARCH: 03, 05, 07, 10, 12, 14).
- Sessões entram sempre com status **agendada** `[LOCKED]`; o preview diz "agendadas" para reforçar.

## Acessibilidade

- Chips: `aria-pressed`, `aria-label` completo, alvo ≥ 44px de altura, foco visível por teclado (Tab percorre os 7; Espaço/Enter alternam).
- Grupo com `role="group"` + rótulo associado.
- Preview em `role="status"`/`aria-live="polite"` para anunciar mudança de total.
- Campo numérico mantém `label` associado e `hint` via `aria-describedby` (comportamento do `Input`).
- Cor nunca é o único indicador: marcado = fundo escuro **e** `aria-pressed`.
